**Goal:** Add the intelligence layer on top of the working P1 funnel — AI matching, a RAG tech
knowledge base feeding source-cited interview questions, a tenant/role-scoped chat assistant,
plus recruiter/candidate polish, analytics, and SSO — multi-tenant, audited, offline-testable.

**Architecture:** Reuse every P1 pattern. New external pieces (Gemini **embeddings**, **Qdrant**,
web **crawl**, OAuth providers) sit behind **injected seams** exactly like P1's fake-LLM, so the
whole phase is built + unit-tested **offline + gate-green**; live validation (retrieval quality,
real SSO) defers to when the Gemini key + Qdrant + OAuth creds are available.

**Tech stack adds:** `qdrant-client`, `rank-bm25`, `httpx` + `beautifulsoup4` (crawler),
Gemini embeddings (via the existing provider seam); Qdrant container in `docker-compose.yml`.
Frontend reuses Next.js 15 / connect-web / TanStack Query / `@ip/{ui,shared,api-client}`.

## Global Constraints
- **No git/gh ever.** Backend gate after each backend task: `bash scripts/check.sh` must stay
  green (baseline **263 tests**). Frontend: `--filter @ip/candidate build` + `--filter @ip/company
  build` + packages `typecheck`. Transport smoke: `scripts/smoke_login.py --selftest`.
- **TDD**, reusing the injected-seam fixtures (`fake_llm`, `fake_data`, `fake_capability`,
  `FakeRedis`, …) and the prompt-fencing helper (`_prompt_safety.fence`).
- **§10.5 regression is sacred:** every P1 acceptance test stays green throughout.
- **Two P2 acceptance properties are first-class from the start:** (a) **chat privacy** — the
  `mcp-data` scope-guard + adversarial tests (§10.3); (b) **matching determinism** — cached
  embeddings + temp-0 (§10.1).
- **Live-only acceptance** (deferred to when key/infra exist): §10.2 "hybrid beats pure-vector"
  (needs a real index), real-provider SSO, real-Gemini chat/RAG quality.

## Locked decisions (recommended — override on review)
1. **Chat transport = candidate/company browser → ai-agents REST `POST /chat/turn` with SSE
   streaming**, scope-enforced at the `mcp-data` tool layer. *Why:* the browser↔admin path is the
   in-house gRPC-web translator, which is **unary-only**; chat is request→streamed-response (no
   duplex needed), and the P1 **interview already runs browser→ai-agents REST** — so chat mirrors
   it instead of adding a new WebSocket transport to admin. The spec said "admin WS host"; this is
   a deliberate simplification consistent with the P1 interview choice. Privacy is enforced where
   it must be (the data layer), not the transport.
2. **SSO transport = REST routes on the admin uvicorn ASGI app** (`/auth/oauth/authorize` redirect
   + `/auth/oauth/callback`), routed alongside the `GrpcWebASGI` translator by a tiny path-prefix
   dispatcher. *Why:* OAuth callbacks are HTTP redirects, not RPC; admin is already ASGI.
   Registration/login stay gRPC; OAuth is REST. Behind a **fake token-exchange client** offline.
3. **Embeddings/Qdrant/crawl = seams** (`Embedder`, `VectorStore`, `Fetcher`) with Gemini/Qdrant/
   httpx implementations + in-memory fakes. Matcher + RAG + chat are unit-tested against the fakes.
4. **Build order = §8** (foundation → matching → RAG questions → chat → polish → analytics+SSO),
   because matching/RAG/chat all depend on the §8.1 embed/kb_search primitives.

## WORKSTREAM 1 — RAG/embeddings foundation (mcp-capability + Qdrant) [§8.1]
*Everything else depends on this. Build entirely behind seams.*

### T1.1 — Seams + deps + infra
**Files:** new `src/mcp-capability/app/seams/{embedder,vector_store,fetcher}.py`; edit
`pyproject.toml` (add `qdrant-client`, `rank-bm25`, `httpx`, `beautifulsoup4`); edit
`docker-compose.yml` (Qdrant service + volume + healthcheck); `src/mcp-capability/app/config.py`
(`qdrant_url`, `gemini_embed_model`, `redis_url`).
- **Change:** each seam = an abstract duck-typed interface + a real impl + a `Fake*` impl.
  `Embedder.embed(texts)->list[vec]` (GeminiEmbedder via the LLM provider key; FakeEmbedder →
  deterministic hash-based vectors). `VectorStore.upsert/search(collection, …)` (QdrantVectorStore;
  in-memory FakeVectorStore with cosine top-k). `Fetcher.fetch(url)->{text,url}` (httpx+BS4 →
  Playwright stretch; FakeFetcher with canned responses).
- **Test:** seam fakes behave (FakeEmbedder deterministic; FakeVectorStore upsert+search top-k).
- **Verify:** gate green (pip-audit must still pass — pin clean versions).

### T1.2 — Semantic chunking + content-hash dedup
**Files:** new `src/mcp-capability/app/chunking.py`; `tests/test_chunking.py`.
- **Change:** `chunk(text, window=1024, overlap=128) -> list[str]` (sentence-aware) + `content_hash`
  (sha256) per chunk.
- **Test:** window/overlap honored; identical text → identical hash; tiny text → one chunk.

### T1.3 — Hybrid retrieval (dense + BM25 + RRF)
**Files:** new `src/mcp-capability/app/retrieval.py`; `tests/test_retrieval.py`.
- **Change:** `hybrid_search(query, *, embedder, store, collection, k)` — dense (embed→store.search)
  + BM25 (`rank-bm25` over candidate chunk texts) fused by **RRF**; returns ranked chunks + sources.
- **Test (offline):** with fake vectors + known BM25 terms, RRF orders a keyword-hit above a pure
  semantic-only hit; tenant `collection` scoping respected. *(Live "beats pure-vector" = deferred.)*

### T1.4 — `embed` / `kb_search` / `ingest` tools
**Files:** edit `src/mcp-capability/app/{tools.py,server.py}`; new `app/schemas.py`;
`tests/test_kb_tools.py`.
- **Change:** `embed(texts)`; `kb_search(query, topic, k)` (Redis-cached, hybrid, tenant/topic
  collection, citations from `kb_sources`); `ingest(owner, sources)` (fetch→chunk→hash→dedup→embed
  →upsert + write `kb_sources` provenance). Wire `@mcp.tool()` over the seams in `server.py`.
- **Test:** kb_search cache hit/miss; ingest dedups by content_hash; ingest then kb_search returns a
  citation; tenant collections isolated.
- **Verify:** gate green.

### T1.5 — ai-agents capability gateway
**Files:** edit `src/ai-agents/app/infra/mcp_capability.py` (+ `embed`, `kb_search`, `ingest`);
`src/ai-agents/tests/conftest.py` (`fake_capability` gains those methods + a `fake_embedder` / a
`fake_kb` returning canned topic→chunks); `test_mcp_clients.py`.
- **Test:** gateway forwards args + `unwrap`s results.
- **Verify:** gate green.

## WORKSTREAM 4 — Chat assistant (scoped, streamed, cited) [§8.4]
*Chat privacy (§10.3) is the headline risk — build the scope-guard + adversarial tests FIRST.*

### T4.1 — mcp-data chat-scope tools (privacy boundary)
**Files:** `src/mcp-data/app/{tools.py,server.py}` (+ `list_applicants(owner_ctx, job_id)`,
`get_application_status(owner_ctx, application_id)`); `src/ai-agents/app/infra/mcp_data.py` (+
gateway methods); `src/mcp-data/tests/test_chat_scope.py`.
- **Change:** every call takes a scope context `{comp_id, role, user_id}` and **re-checks**
  comp_id + role + relationship: recruiter → only applicants to their own jobs; candidate → only
  their own application. Reject otherwise. (Extends the audit's tenant-isolation work.)
- **Test (adversarial):** recruiter asking for a non-applicant → empty/denied; candidate asking
  for another's status → denied; cross-tenant → denied.
- **Verify:** gate green.

### T4.2 — Assistant agent (Planner-routed)
**Files:** new `src/ai-agents/app/resources/assistant.py`; `tests/test_assistant.py`.
- **Change:** `assistant_turn(messages, ctx, *, llm, data, capability)` — a Planner LLM routes to:
  job-question → `kb_search` (cited); status → `get_application_status`; ranking →
  `list_applicants`. All untrusted text **fenced** (`_prompt_safety.fence`); answers carry citations.
- **Test:** routing picks the right tool; scope ctx threaded to every data call; injected
  "ignore instructions" in a message is fenced.

### T4.3 — ai-agents `/chat/turn` SSE endpoint
**Files:** `src/ai-agents/app/routes/interview_api.py` (or new `chat_api.py`) — `POST /chat/turn`

`chat_sessions`/`chat_messages` persistence via mcp-data; `tests/test_chat_api.py`.
- **Change:** authenticate, build scope ctx from the JWT, stream `assistant_turn` chunks as SSE.
- **Test:** 401 without token; scope ctx derived from claims; stream emits text+citation events.
- **Verify:** gate green.

### T4.4 — Frontend chat UI
